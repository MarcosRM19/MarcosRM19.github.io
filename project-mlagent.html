Unity AI MachineLearning

Engine-native autonomous combat agent built with Unity ML-Agents and PPO for a 3D tank combat simulation.

Investigación DRL / Mini-TFG Unity ML-Agents v2.0 + PyTorch

Agente Autónomo de Combate 3D mediante Aprendizaje por Refuerzo Profundo

Objetivos del Proyecto

El objetivo de este proyecto es el de desarrollar un agente capaz de dominar las mecánicas de un simple juego de tanques 3D mediante la herramienta de ML-Agent. El reto reside en que el agente adquiera habilidades competitivas de forma autónoma, sin la necesidad de programar comportamientos lógicos manuales o sistemas basados en reglas.

A su vez se pretende investigar como el Self-Play permite la emergencia de estrategias tácticas complejas en el entorno que serían complejas de codificar de manera tradicional. Enfatizando en una IA que evoluciona adaptándose durante el proceso de entrenamiento.

Formulación del Problema y Proceso de Decisión de Markov (POMDP)

Para lograr que el agente aprenda sin reglas codificadas a mano, el escenario de combate vehicular se modeló rigurosamente como un Proceso de Decisión de Markov Parcialmente Observable (POMDP) definido por la tupla $\langle S, A, P, R, \gamma \rangle$:

Formulación del Entorno

  • Espacio de Estados ($S$): Representación continua multidimensional con cinemática local, Raycasts y sensores de orientación.
  • Espacio de Acciones ($A$): Control híbrido de 3 continuas (tracción, dirección, torreta) y 1 discreta (disparo).
  • Transiciones ($P$): Dinámica física de tracción en Unity acelerada para entrenamiento masivo.
  • Recompensas ($R$): Función de ajuste continuo mediante ingeniería de recompensas (Reward Shaping).

Objetivo de Optimización

El agente optimiza una política estocástica $\pi_\theta(a|s)$ parametrizada mediante una red neuronal para maximizar la recompensa acumulada con descuento temporal:

J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta} \left[ \sum_{t=0}^{T} \gamma^t R(s_t, a_t) \right] \quad \text{con } \gamma = 0.99

Espacio de Observaciones Vectoriales y Sensores 3D

Toda la percepción del entorno proviene de sensores locales sobre el tanque, sin acceder a datos globales o tramposos de la simulación.

03

Algoritmo PPO y Arquitectura Actor-Critic

Red Neuronal Multicapa (MLP)

  • Input: Vector normalizado de 27 observaciones.
  • Capas Ocultas: 2 capas densas de 256 neuronas cada una.
  • Actor ($\pi_\theta$): Genera acciones continuas de conducción y decisión discreta de disparo.
  • Critic ($V_\phi$): Estima el valor del estado para calcular ventajas acumuladas.

Optimización PPO Clipped

PPO acota las actualizaciones mediante un margen $\epsilon = 0.2$ para garantizar que el entrenamiento no destruya comportamientos útiles previamente consolidados:

L^{CLIP}(\theta) = \hat{\mathbb{E}}_t \left[ \min(r_t(\theta)\hat{A}_t, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t) \right]

Ingeniería de Recompensas (Reward Shaping)

Función de Recompensa General
R_{\text{total}} = R_{\text{impacto}} (+1.0) + R_{\text{alineación}} (+0.05 \cdot \cos\theta) - R_{\text{tiempo}} (-0.001) - R_{\text{muro}} (-0.25) - R_{\text{fallo}} (-0.05)

Emergencia de Estrategias con Self-Play

Al enfrentar al agente contra un "Model Pool" de sus versiones pasadas, se evita la memorización de patrones rígidos. Esto permite la aparición autónoma de tácticas avanzadas como disparar tras muros (peek-a-boo) y mantener ángulos de evasión.

Configuración YAML de Entrenamiento

trainer_config_tank_ppo.yaml 
behaviors:
  TankAgent:
    trainer_type: ppo
    hyperparameters:
      batch_size: 2048
      buffer_size: 20480
      learning_rate: 0.0003
      beta: 0.005
      epsilon: 0.2
      lambd: 0.95
      num_epoch: 3
    network_settings:
      normalize: true
      hidden_units: 256
      num_layers: 2
    reward_signals:
      extrinsic:
        gamma: 0.99
        strength: 1.0
    self_play:
      save_steps: 50000
      team_change: 200000
      swap_steps: 2000
      window: 10
